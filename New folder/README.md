# Pygmy — AI-Native Data Operations Platform

> Self-hosted pipeline observability, quality rule management, and conversational data engineering assistance powered by a fine-tuned LLM.

---

## Overview

Pygmy is a data operations platform built for engineering teams who need real-time observability across a heterogeneous data stack — without routing sensitive credentials or query results through third-party services. All model inference, storage, and execution remain on-premise.

The platform combines:
- A **fine-tuned LLM** (`pipeline-qwen-sft`, based on Qwen 70B Instruct) for domain-accurate pipeline reasoning
- A **five-source quality engine** that merges system tests, live connector results, LLM-generated rules, log patterns, and watchdog alerts
- A **typed connector framework** for Snowflake, PostgreSQL, Kafka, S3, Looker, Airflow, dbt, and Fivetran
- A **conversational assistant** with red-herring detection, command proposals, and RAG-grounded citations

## Getting Started

### Prerequisites

- Node.js 18+
- [Ollama](https://ollama.ai) running locally
- MongoDB Atlas connection string
- Qdrant Cloud API key
- (Optional) Snowflake, PostgreSQL, Kafka credentials for live connectors

### Install

```bash
npm install
```

### Environment Variables

Create a `.env` file at the project root:

```env
# MongoDB
MONGODB_URI=mongodb+srv://<user>:<pass>@cluster.mongodb.net/pygmy

# Qdrant
QDRANT_URL=https://<cluster>.qdrant.io
QDRANT_API_KEY=your_qdrant_api_key

# Ollama (defaults shown)
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_CHAT_MODEL=qwen2.5:7b-instruct
OLLAMA_FAST_CHAT_MODEL=llama3.2:1b
OLLAMA_TUNED_MODEL=pipeline-qwen-sft

# Custom model service (optional)
MODEL_SERVICE_URL=http://127.0.0.1:8000
```

### Run

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

## Model

### pipeline-qwen-sft

`pipeline-qwen-sft` is Qwen 70B Instruct fine-tuned on pipeline operations data:

- Query failure patterns (Snowflake, PostgreSQL)
- dbt lineage errors and dependency failures
- Airflow DAG failure logs
- Snowflake `ACCOUNT_USAGE` anomaly patterns
- Red-herring incident reports with root cause annotations

The model is served as a Q4_K_M GGUF via llama.cpp through a custom model service at `localhost:8000`. Ollama is used as the fallback runtime.

### Model Routing

| Path | Model | Trigger |
|---|---|---|
| Fast | `llama3.2:1b` | Greetings, role inference, short queries |
| Deep | `pipeline-qwen-sft` | Diagnosis, root cause analysis |
| Remedy | `pipeline-qwen-sft` | Fix, resolve, retry requests |
| Red-Herring | `pipeline-qwen-sft` | error / fail / stale / incident signals |

Each path has a fallback chain tried in order if the preferred model is unavailable.

## Quality Engine

Five independent rule sources merged at query time via `mergeQualityBundles()`:

| Source | Generated By | Cache TTL |
|---|---|---|
| System Tests | Deterministic TypeScript | Per request |
| Live Connector | Live queries to connected tools | 10 min |
| QA Agent | `pipeline-qwen-sft` | 20 min |
| Log Monitor | Log pattern extraction | Per request |
| Watchdog | Real-time anomaly detection | Per snapshot |

### Severity Levels

| Level | Meaning |
|---|---|
| SEV-1 | Critical — data loss or full outage |
| SEV-2 | Major — blocked pipeline |
| SEV-3 | Warning — degraded quality |
| SEV-4 | Info — observation only |

## Connectors

Commands against live systems require explicit user approval before execution. Read-only actions (`query`, `fetch_logs`, `validate`, `fetch_metadata`, `inspect`, `discover`, `test_connection`) execute immediately. Mutating actions (`restart`, `refresh`, `trigger`) are approval-gated.

Supported connectors: **Snowflake · PostgreSQL · Kafka · S3/GCS · Looker · Airflow · dbt Cloud · Fivetran**

## Benchmark Evaluation

`pipeline-qwen-sft` was evaluated against two baselines on [DCA-Bench](https://huggingface.co/datasets/trais-lab/DCA-Bench) — a standardised benchmark for data-centric anomaly detection.

**Configuration:** 30 cases, hint level -1 (no hints), max 450 tokens per response.

| Model | Heuristic Score | Avg. Response Length |
|---|---|---|
| **pipeline-qwen-sft** | **1.000** | **113.6 words** |
| Gemma-3 27B QAT | 1.000 | 183.4 words |
| DeepSeek-R1-Distill-Qwen-7B | 1.000 | 315.3 words |

All models achieved perfect heuristic detection. `pipeline-qwen-sft` produced the most concise outputs — 1.6x shorter than Gemma-3 and 2.8x shorter than DeepSeek-R1 — demonstrating that domain-specific fine-tuning enables targeted responses without sacrificing coverage.

Full evaluation methodology and results are in [`public/pygmy-technical-docs.pdf`](public/pygmy-technical-docs.pdf).
